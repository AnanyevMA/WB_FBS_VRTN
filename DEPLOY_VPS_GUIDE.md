## 1. Архитектура оптимизации под 1 GB RAM

На сервере с 1 ГБ оперативной памяти запуск нескольких контейнеров в стандартных настройках может вызвать нехватку памяти (OOM Crash). В нашем проекте реализована **специальная легковесная конфигурация**:

- **Swap 2 GB**: Автоматически создается и настраивается скриптом `setup_vps.sh` с параметром `swappiness=10` (защита от падений при пиковых нагрузках).
- **PostgreSQL 16**: Ограничен буфер памяти (`shared_buffers=64MB`, `max_connections=30`).
- **Redis 7**: Ограничен лимит памяти до 64 MB с политикой вытеснения `allkeys-lru`.
- **FastAPI (Uvicorn)**: 1 асинхронный воркер с лимитом соединений (потребление ~80 MB).
- **Celery Worker**: Запускается с `--concurrency=2` и `--max-tasks-per-child=100` для предотвращения утечек памяти.
- **Nginx**: Оптимизирован под 1 ядро (`worker_processes 1`, `worker_connections 512`), отдает статику напрямую и сжимает ответы через gzip.
- **Docker Logs**: Ограничены до 10 МБ на файл (максимум 3 файла), что защищает диск 30 ГБ от переполнения.

**Итоговое потребление RAM:** ~540–580 МБ (остается более 400 МБ запаса оперативной памяти).

## Шаг 1: Публикация проекта на GitHub

Выполните на вашем локальном компьютере:

```bash
# 1. Перейдите в папку проекта
cd "d:/PyCharm_Projects/WB FBS"

# 2. Инициализируйте Git-репозиторий (если еще не инициализирован)
git init

# 3. Проверьте статус (убедитесь, что .env, wbfbs.db, certs/* исключены благодаря .gitignore)
git status

# 4. Добавьте файлы и сделайте первый коммит
git add .
git commit -m "feat: initial production-ready commit for GitHub and VPS"

# 5. Создайте репозиторий на GitHub (например, wb-fbs-manager)
# 6. Привяжите удаленный репозиторий и отправьте код:
git branch -M main
git remote add origin https://github.com/AnanyevMA/WB_FBS_VRTN.git
git push -u origin main
```

## Шаг 2: Первоначальная настройка VPS

Подключитесь к вашему VPS по SSH:

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

Установите `git` и клонируйте проект в каталог `/opt/wb-fbs`:

```bash
mkdir -p /opt
cd /opt
git clone https://github.com/AnanyevMA/WB_FBS_VRTN.git wb-fbs
cd /opt/wb-fbs
```

Запустите автоматический скрипт настройки сервера:

```bash
chmod +x scripts/*.sh docker/entrypoint.sh
./scripts/setup_vps.sh
```

**Что делает `setup_vps.sh`:**
- Обновляет пакеты ОС;
- Создает и активирует 2 GB Swap-файл;
- Устанавливает Docker CE и Docker Compose;
- Настраивает фаервол UFW (открывает порты 22, 80, 443, закрывает порты БД 5432 и 6379 от внешнего доступа);
- Включает Fail2ban для защиты SSH;
- Настраивает ротацию логов Docker.

## Шаг 3: Клонирование и генерация секретов

Сгенерируйте файл `.env` с уникальными криптографическими ключами:

```bash
python3 scripts/generate_secrets.py
```

Откройте `.env` для редактирования и при необходимости укажите персональные настройки:

```bash
nano .env
```

Основные параметры:
- `SECRET_KEY`, `JWT_SECRET_KEY`, `ENCRYPTION_KEY` — сгенерированы автоматически.
- `POSTGRES_PASSWORD` — сгенерирован автоматически.
- `DEBUG=false` — режим продакшн.

Сохраните файл (`Ctrl + O`, затем `Enter`, выход `Ctrl + X`).

## Шаг 4: Запуск проекта в Production

Соберите и запустите все сервисы:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Проверьте статус всех контейнеров:

```bash
docker compose -f docker-compose.prod.yml ps
```

Проверьте потребление памяти и ресурсов:

```bash
./scripts/check_memory.sh
```

Проверьте доступность API:

```bash
curl http://127.0.0.1/health
# Ответ: {"status":"ok","version":"1.0.0","service":"WB FBS Manager"}
```

На этом этапе проект уже доступен в браузере по IP-адресу сервера: `http://IP_ВАШЕГО_СЕРВЕРА`.

## Шаг 5: Настройка домена и SSL (Let's Encrypt)

Для полноценной работы веб-интерфейса и вебхуков Telegram рекомендуется настроить домен и бесплатный HTTPS-сертификат.

1. В панели управления вашим доменом (Reg.ru, Beget, Cloudflare, Timeweb и др.) создайте **A-запись**:
   - Имя: `@` (или поддомен, например `fbs`)
   - Значение: `IP_ВАШЕГО_СЕРВЕРА`
   - TTL: `300` (5 минут)

2. Дождитесь обновления DNS (2–10 минут).

3. Запустите скрипт автоматического выпуска SSL-сертификата:

```bash
./scripts/init_ssl.sh yourdomain.ru admin@yourdomain.ru
```

Скрипт:
- Выпустит официальный сертификат Let's Encrypt;
- Обновит конфигурацию Nginx с HTTP на HTTPS (TLS 1.2/1.3, HSTS);
- Настроит автоматическое продление сертификата каждые 60 дней.

Теперь ваш сервис защищен и доступен по адресу: `https://yourdomain.ru`.

## Шаг 6: Автозапуск при перезагрузке ОС (Systemd)

Чтобы проект автоматически поднимался после перезагрузки сервера:

```bash
cp systemd/wb-fbs.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable wb-fbs.service
```

## Шаг 7: Автоматическое резервное копирование (Cron)

Настройте ежедневный бэкап базы данных PostgreSQL в 04:00 утра:

```bash
crontab -e
```

Добавьте в конец файла строку:

```cron
0 4 * * * /opt/wb-fbs/scripts/backup_db.sh >> /opt/wb-fbs/logs/backup.log 2>&1
```

Бэкапы сохраняются в `/opt/wb-fbs/backups/` в сжатом виде (`.sql.gz`). Копии старше 14 дней удаляются автоматически.

## Шаг 8: Обновление проекта (Деплой новой версии)

Когда вы внесли изменения в код и отправили их на GitHub (`git push`):

На сервере достаточно выполнить одну команду:

```bash
./scripts/deploy.sh
```

Скрипт автоматически:
1. Скачает свежий код (`git pull`);
2. Пересоберет Docker-контейнеры;
3. Применит новые миграции БД (`alembic upgrade head`);
4. Перезапустит сервисы без простоя;
5. Очистит старые Docker-образы для экономии диска;
6. Проверит статус `/health`.

## Шаг 9: Настройка КриптоПро и сертификатов УКЭП

Если вы используете усиленную квалифицированную электронную подпись (УКЭП) для системы Честный Знак:

1. Скопируйте файлы сертификатов (`.cer`, `.pfx` или контейнеры ключей) в директорию `/opt/wb-fbs/certs/`.
2. В файле `.env` укажите отпечаток сертификата:
   ```env
   CRYPTOPRO_CERT_THUMBPRINT=ваш_отпечаток_сертификата
   ```
3. Перезапустите воркеры:
   ```bash
   docker compose -f docker-compose.prod.yml restart worker api
   ```

## Диагностика и полезные команды

### Просмотр логов:
```bash
# Все логи в реальном времени
docker compose -f docker-compose.prod.yml logs -f

# Логи конкретного сервиса
docker compose -f docker-compose.prod.yml logs -f api
docker compose -f docker-compose.prod.yml logs -f worker
docker compose -f docker-compose.prod.yml logs -f bot
docker compose -f docker-compose.prod.yml logs -f postgres
```

### Проверка памяти и диска:
```bash
./scripts/check_memory.sh
```

### Ручное создание бэкапа:
```bash
./scripts/backup_db.sh
```

### Вход в консоль PostgreSQL:
```bash
docker compose -f docker-compose.prod.yml exec postgres psql -U wbfbs -d wbfbs
```

### Запуск веб-панели Flower (по требованию для экономии RAM):
```bash
# Запустить Flower (будет доступен по адресу http://IP_СЕРВЕРА:5555)
docker compose -f docker-compose.prod.yml --profile monitoring up -d flower

# Остановить Flower для освобождения RAM
docker compose -f docker-compose.prod.yml stop flower
```

## 1. Ошибки Wildberries Marketplace API

### Ошибка: `409 Conflict — MetaValidationFail`
- **Симптом**: При попытке закрыть поставку (`PATCH /api/v3/supplies/{id}/deliver`) или передать заказ в доставку WB возвращает статус 409 с телом `{"error": "MetaValidationFail", "message": "KIZ required for item..."}`.
- **Первопричина**: В составе сборочных заданий есть товар из маркированной категории («Честный Знак»), для которого не был передан или не прошел валидацию SGTIN код.
- **Готовое Решение**:
  1. Выполнить проверку заказов в поставке через `GET /api/v3/supplies/{id}/orders`.
  2. Для каждого заказа проверить наличие `orders.kiz_status == 'ATTACHED'`.
  3. Отсканировать DataMatrix код и привязать через `PUT /api/v3/orders/{orderId}/meta/sgtin`.
  4. Повторить закрытие поставки после получения статуса `VALIDATED`.

---

### Ошибка: `429 Too Many Requests`
- **Симптом**: WB API возвращает 429 с сообщением `Rate limit exceeded`.
- **Первопричина**: Превышен лимит 300 запросов в минуту на один токен продавца.
- **Готовое Решение**:
  1. Проверить интервалы в `app/celery_app.py` (опрос заказов не чаще 60 секунд на селлера).
  2. Убедиться, что в `app/services/wb_client.py` включен Exponential Backoff:
     ```python
     wait=wait_exponential(multiplier=1, min=2, max=10)
     ```
  3. Проверить очереди Celery: не запускать более 5 параллельных задач на одного селлера.

---

### Ошибка: `401 Unauthorized`
- **Симптом**: `Invalid or expired API token`.
- **Первопричина**: Продавец отозвал или пересоздал токен в личном кабинете WB, либо истек срок его действия.
- **Готовое Решение**:
  1. Сгенерировать новый токен в ЛК WB (*Настройки → Доступ к API*).
  2. В UI сервиса открыть карточку селлера и нажать «Обновить токен».
  3. Нажать кнопку «Проверить подключение» (`POST /api/v1/sellers/{id}/test-connection`).

## 2. Ошибки ГИС МТ (Честный Знак / True API / СУЗ)

### Ошибка: `401 Unauthorized / Token Expired`
- **Симптом**: Запросы к True API или СУЗ отклоняются с кодом 401.
- **Первопричина**: Сессионный токен True API живет до 10 часов и истек.
- **Готовое Решение**:
  1. Запустить агент обновления токенов: `app.agents.cz_token_refresher.refresh_all_tokens`.
  2. Проверить доступность закрытого ключа УКЭП для автоматического переподписания challenge.

---

### Ошибка: Документ ГИС МТ отклонен (`REJECTED: KIZ NOT IN CIRCULATION`)
- **Симптом**: При асинхронной проверке документа `LP_SHIP_GOODS` возвращается статус `REJECTED`.
- **Первопричина**: КИЗ находится в статусе `EMITTED` (эмитирован) или `APPLIED` (нанесен), но не был введен в оборот (`INTRODUCED`), либо уже был ранее выведен из оборота.
- **Готовое Решение**:
  1. Выполнить запрос `POST /api/v3/true-api/cises/info` по коду товара.
  2. Если статус `APPLIED` — отправить документ ввода в оборот `LP_INTRODUCE_GOODS` от имени производителя/импортера.
  3. Если КИЗ чужой организации — проверить корректность УПД от поставщика.

## 3. Ошибки КриптоПро CSP и Электронной Подписи

### Ошибка: `Certificate Thumbprint Not Found (Код 0x80090016 / 0x80092004)`
- **Симптом**: `csptest` или `pycades` выдают ошибку «Контейнер закрытого ключа не найден».
- **Первопричина**: Не установлен личный сертификат в хранилище `uMy`, либо не сопоставлен контейнер закрытого ключа.
- **Готовое Решение**:
  1. Запустить команду проверки хранилища:
     ```bash
     /opt/cprocsp/bin/amd64/certmgr -list -store uMy
     ```
  2. Проверить соответствие SHA-1 хеша значению в настройках продавца (`seller.cryptopro_cert_thumbprint`).
  3. Проверить срок действия сертификата и наличие действующей лицензии КриптоПро CSP (`/opt/cprocsp/sbin/amd64/cpconfig -license -view`).

---

### Ошибка: `Invalid Signature / Неверная ЭП (Секция 2.3.1 СУЗ 3.0.38)`
- **Симптом**: СУЗ отклоняет запрос с ошибкой «Подпись в заголовке X-Signature не прошла проверку».
- **Первопричина**: Нарушение каноникализации JSON — пробелы, переносы строк `\r\n`, экранирование `ensure_ascii=True` вместо `UTF-8`.
- **Готовое Решение**:
  1. Сериализовать JSON строго через `json.dumps(body, ensure_ascii=False, separators=(',', ':'))`.
  2. Для `GET`-запросов подписывать строку `PATH + QUERY` (например, `/api/v3/order/status?omsId=...&orderId=...`).
